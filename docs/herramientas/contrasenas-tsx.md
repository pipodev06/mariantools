# Contrasenas.tsx

- **`Contrasenas.tsx`** (`/contrasenas`) — generador de contraseñas, 100% client-side, sin dependencias externas de red (`crypto.getRandomValues`, nunca `Math.random` — importante para una tool que se llama "seguras"). **Rompe a propósito el patrón de "flujo de dos pantallas"** de Ocr/Base64: acá la config queda siempre visible y el resultado se regenera reactivo, sin pantalla de "resultados" separada ni botón "Volver a empezar" — tiene más sentido para una tool de "seguir generando/ajustando" que para una de convertir-y-listo. **Esto es intencional y no un desvío**: el usuario confirmó explícitamente (2026-08-14) que el patrón de dos pantallas de Ocr no es universal — cada tool nueva puede tener su propia interfaz según lo que tenga más sentido para ese tipo de herramienta, no hay que forzar todo al mismo molde.
  - **Layout: grid de 2 columnas** (`lg:grid-cols-[auto_auto] lg:justify-center`, apila a 1 columna en mobile) — **config** | columna derecha apilada con **contraseña destacada + Regenerar**, **puntuación de seguridad**, y **"Más contraseñas"** (en ese orden). Pasó por 2 iteraciones: arrancó como grid de 3 columnas (config | destacada+mas | puntuación aparte) imitando a Proton Pass; el usuario después pidió explícitamente pasar a un layout de 2 columnas tipo wireframe ("split — options left, result right"), con la puntuación movida adentro de la columna derecha en vez de ser su propia columna. Todas las cards usan el patrón **glassmorphism ya congelado** (`bg-white/60 dark:bg-slate-800/40 backdrop-blur-md border border-white/40 dark:border-slate-700/40`, con el gradiente decorativo `from-emerald-200/40 via-transparent to-slate-200/40` detrás de todo el grid) — nunca la paleta violeta de Proton, a propósito, para que no se vea como una copia.
  - **Puntuación de seguridad: 5 cuadraditos + label al costado, no gauge circular.** Se probaron 2 versiones antes de esta: primero un semicírculo SVG (`pathLength`+`strokeDasharray`, ver commits viejos si hace falta recuperar la técnica), después una barra de 5 pastillas finas con el label DEBAJO — el usuario pidió explícitamente cuadraditos (no pastillas) y el label AL COSTADO (misma fila), no debajo. Implementación final: `filledBars = Math.max(1, Math.min(5, Math.ceil((bits / MAX_ENTROPY_BITS) * 5)))` (bits de entropía normalizados a una escala de 0-5, no los 3 saltos categóricos de antes — da feedback más fino al mover la config), 5 `<div>` de `h-5 w-10 sm:w-20` (20px alto × 80px ancho desde `sm:`, 40px ancho por default en mobile — ojo, no son cuadrados perfectos pese al nombre "cuadraditos" del pedido original, el usuario ajustó a esta proporción rectangular después) con `gap-1` (4px) entre ellos, coloreados con `strength.bar` (`bg-red-500`/`bg-amber-500`/`bg-emerald-500` — mismo semáforo de 3 colores ya documentado como excepción a la paleta, ahora aplicado a bloques en vez de a un badge) si están "llenos" o `bg-slate-200 dark:bg-slate-800` si no. El label (`Débil`/`Media`/`Fuerte`) va en un `<span>` badge al lado, mismo `flex items-center gap-3`. **Bug real encontrado al revisar mobile**: con las 5 barras en `w-20` (80px) fijo sin variante responsive, el ancho mínimo del bloque de barras (5×80 + 4×4 de gap = 416px) no entraba en el ancho disponible de una card en un celular angosto (~310px de contenido después de padding de página+card) — se iba a desbordar horizontalmente. Se agregó `w-10` como base (mobile) y `sm:w-20` desde 640px — mismo criterio a aplicar si se agrega otro elemento de ancho fijo grande a esta página: siempre pensar en el caso `max-lg:w-full` (mobile/tablet, cuando la card deja de tener su ancho fijo de desktop) antes de fijar anchos internos también fijos.
  - **Título (H1 + subtítulo) alineado al ancho del card de config**: envueltos en `<div className="mx-auto w-100 max-lg:w-full">` (mismo `w-100` que el card de config) en vez de quedar sueltos a lo ancho de la sección — pedido explícito del usuario (2026-08-14) para que el bloque de título no se vea descentrado/desproporcionado respecto al grid de 2 columnas de abajo, que sí está centrado (`lg:justify-center`).
  - Contenedor de página más ancho que el resto del sitio: `max-w-[100rem]` (valor arbitrario, no un paso de la escala `max-w-*` estándar — pedido explícito del usuario porque `max-w-7xl` todavía se sentía angosto para un layout de 3 columnas). Tipografía también un paso más grande que el resto de las tool pages (`text-base` en vez de `text-sm` para labels/opciones, `text-2xl` para la contraseña destacada) — sigue usando pasos de la escala congelada, solo elige escalones más grandes que el default para esta página en particular.
  - **Sin `font-mono` ni `<code>`** — Manrope para todo, incluida la contraseña mostrada (ver regla en `## Tipografía`). Contraseñas se muestran en `<span>`/`<p>` con `break-all`.
  - **Dos modos** (toggle "Random"/"Memorable", segmented control arriba de la config — mismo patrón de pill-toggle que el de formato en `ImagenABase64.tsx`):
    - **Random**: charset por tipo de carácter (igual que antes).
    - **Memorable**: passphrase estilo diceware (agregado en una segunda pasada, después de que el usuario pidiera explícitamente sumarlo — el alcance inicial lo había descartado para evitar la dependencia de una wordlist, pero el pedido posterior de imitar el generador de Proton Pass lo trajo de vuelta). Palabras de **`src/lib/wordlist.ts`** — la wordlist oficial BIP39 en inglés (2048 palabras, estándar de la industria para passphrases: sin ambigüedades ni acentos, dominio público), bajada de `raw.githubusercontent.com/bitcoin/bips/master/bip-0039/english.txt` (pedido permiso al usuario antes de bajar el archivo). Config: cantidad de palabras (slider 3-8), mayúsculas (capitaliza cada palabra), números (dígito random al final de cada palabra), y **separador** — guion/espacio/punto/coma/guion bajo literales, o "Números"/"Números y símbolos" que generan un separador random por hueco en vez de un carácter fijo, sumando entropía real.
    - **Separador: dropdown propio, no `<select>` nativo** (`separatorOpen` + `separatorRef`, patrón botón-trigger + `<ul role="listbox">` absoluto, cierra con click-afuera y `Escape` vía `useEffect` con listeners en `document`/`window`). Se intentó primero con `<select>`/`<option>` nativos estilando el `className` de cada `<option>` — funciona para el fondo/color en Chromium, pero **el hover/selección del popup nativo usa el highlight gris del SO y no se puede recolorear a esmeralda con CSS**, pedido explícito del usuario. El dropdown propio sí tiene hover/seleccionado en emerald (`bg-emerald-50 dark:bg-emerald-500/10`), igual que el resto de opciones clickeables de la página. `max-h-56 overflow-y-auto` en la lista — **sin esto el dropdown puede overflowear visualmente debajo del Footer** (bug real encontrado: el `z-10` del `<ul>` solo gana contra otros elementos dentro del mismo stacking context de `main`, no contra el `<footer>`, que es un sibling posterior en el layout y pinta encima si hay overlap espacial — capar la altura evita el problema de raíz en vez de perseguir z-index). **Ojo**: el popup nativo (y por lo tanto este reemplazo) no se puede probar 100% por screenshot en Chromium headless con algunas interacciones (clicks en coordenadas calculadas fallan si el navegador de pruebas no hace scroll interno del `<ul>` solo); confirmar interacción real en un browser si se vuelve a tocar.
    - **Segundo bug real de stacking, encontrado recién al probar mobile** (en desktop nunca se manifestó porque las columnas van lado a lado y nunca se superponen visualmente): las cards de esta página usan `backdrop-blur-md` (parte del glassmorphism congelado), y **`backdrop-filter` crea su propio stacking context** — el `z-10` del dropdown queda atrapado DENTRO del stacking context de la card de config, así que no puede ganarle a la card de "contraseña destacada" (que tiene su propio `backdrop-blur-md`, su propio stacking context aparte) aunque esta última no tenga z-index — en mobile, donde el grid pasa a `grid-cols-1` y la destacada queda apilada justo debajo de config, el dropdown al abrirse quedaba visualmente tapado por (o mezclado con) esa card de abajo. Fix: `relative z-20` en la card de config completa (no solo en el dropdown), para elevar **todo su stacking context** por encima del de las cards vecinas, sin importar el orden en el DOM. **Regla general para esta página**: si un elemento `absolute`/`z-*` adentro de una card con `backdrop-blur` no se ve por encima de otra card, el problema casi seguro es este — subir el z-index del hijo no alcanza, hay que subir el de la card contenedora entera.
  - **Reactivo, sin botón "Generar"**: la lista se recalcula sola (`useMemo`, deps incluyen `mode` + toda la config de ambos modos + `regenKey`) cada vez que cambia la config. El botón "Regenerar" no cambia config — solo bump de `regenKey` para forzar un nuevo random con la misma config (reroll). **Ojo**: no usar `useEffect` + `setState` para esto (el enfoque inicial, revertido) — el lint del repo (`react-hooks/set-state-in-effect`) lo rechaza porque es estado 100% derivado, `useMemo` es lo correcto acá.
  - **Cantidad de "Más contraseñas" fija** (`ALT_COUNT = 4`, sin slider) — el usuario lo pidió así después de probar el slider original (0-20): siempre se generan 4 alternativas junto a la destacada (bajado de 6 a 4 en un ajuste posterior).
  - **"Más contraseñas" trunca (`truncate`, 1 línea + "…"), la contraseña destacada clampea a 2 líneas (`line-clamp-2 break-all`)** — mismo objetivo (ninguna card cambia de tamaño) pero resuelto distinto en cada una tras varias vueltas de feedback: primero ambas en `truncate`, después el usuario pidió que la destacada **muestre el valor completo** (sin "…") aunque ocupe 2 líneas, en vez de cortarlo — mientras la card padre (alto fijo) no crezca. Como esa card se dimensionó bastante más grande de lo que el contenido necesita en 1 línea (hay bastante aire arriba/abajo por el `flex flex-col items-center justify-center`), 2 líneas de texto entran sin problema dentro del mismo alto fijo, sin necesidad de achicar nada más — confirmado con 64 caracteres (Random) y 8 palabras (Memorable). La lista de "Más contraseñas" sí se quedó en `truncate` (1 línea) — tiene menos aire por fila, y ahí sí tiene sentido priorizar altura uniforme sobre mostrar el valor completo (para eso está el botón copiar + el `title` con el hover).
  - **Las 3 columnas no se redimensionan entre sí al cambiar longitud/cantidad de palabras** — dos bugs reales encontrados comparando contra Proton Pass a 64 caracteres, ambos por comportamiento default de CSS Grid, no visibles a simple vista hasta probar con contenido largo:
    1. El grid de 3 columnas necesita **`items-start`** (si no, `align-items: stretch` por default hace que las 3 columnas se estiren a la altura de la más alta — la columna del medio crecía por el wrap de la contraseña y arrastraba a las otras dos).
    2. La columna del medio (`<div className="flex min-w-0 flex-col gap-6">`) necesita **`min-w-0`** explícito — sin eso, un `<span>` con `truncate` (que usa `white-space: nowrap`) en algún nieto profundo hace que el navegador calcule el "ancho mínimo de contenido" de toda la columna como el string sin cortar más largo, y como los ítems directos de un CSS Grid tienen `min-width: auto` (= min-content) por default, esa columna se agranda más allá de su `1.3fr` y **empuja/achica las columnas vecinas** (exactamente el bug que reportó el usuario: "se mueve o se redimensiona"). `min-w-0` en el ítem del grid corta esa propagación. Si se agrega una columna nueva a este layout con contenido de ancho variable, aplicar el mismo patrón (`min-w-0` en el hijo directo del grid).
    3. La **card de puntuación** también quedó con alto variable por el mismo espíritu de bug, pero de otra forma: el caption de tiempo de crackeo (`{crackTime} para descifrar esta contraseña`) mide 1 o 2 líneas según el largo del texto ("114 siglos..." vs "Millones de siglos..."). Acá **no** se usa `truncate` (es una oración, no un valor a copiar — cortarla a la mitad con "…" se ve mal) sino `min-h-10 line-clamp-2`: reserva altura de 2 líneas siempre (el texto de 1 línea queda con aire de sobra abajo) y clampea si alguna vez fuera más largo.
  - **Dimensiones fijas en px (ancho × alto), pedido explícito del usuario a partir de un wireframe de referencia** — las 4 cards dejaron de ser fluidas y pasaron a tamaño exacto. `max-lg:w-full max-lg:h-auto` en las 4 (mobile vuelve a fluido/auto — el grid ya colapsa a `grid-cols-1` bajo `lg`, el tamaño fijo solo aplica en desktop). Destacada y puntuación llevan además `flex flex-col items-center justify-center` para centrar su contenido verticalmente (antes quedaba pegado arriba con aire de sobra abajo). El `<ul>` de "Más contraseñas" perdió su `max-h-72 overflow-y-auto` propio — el scroll (si hiciera falta) lo maneja la card entera, para no anidar dos scrolls.
  - **`overflow-y-auto` de safety en 3 de las 4 cards, no en la de config** — bug real: la card de config tiene el dropdown de "Separadores" (absolute, `z-10`), y un elemento absolutamente posicionado **sí cuenta** para el scroll-overflow de su ancestro con `overflow` seteado aunque no afecte el flujo normal — con `overflow-y-auto` en esa card, abrir el dropdown (que mide más que el espacio libre) le generaba scrollbar propia a la card entera en vez de flotar por encima. Se sacó `overflow-y-auto` solo de esa card (destacada, "Más contraseñas" y puntuación lo mantienen, no tienen ese problema). Si se agrega otro dropdown/popover absoluto a una card con `overflow-y-auto`, mismo cuidado.
  - **Ancho/alto con la escala numérica de Tailwind, no `w-[Npx]` arbitrario** (pedido explícito del usuario: "que no sea arbitrary value, aproximá al estilo Tailwind más cercano"). En Tailwind v4 cualquier número en `w-*`/`h-*`/`gap-*` resuelve a `calc(var(--spacing) * N)` (`--spacing` = 4px) sin config extra — **no existe** una escala con nombre (`w-xl`, `h-xl`) para `width`/`height` fijos, esa nomenclatura (`xs`...`7xl`) es exclusiva de `max-width` (y no existe en absoluto para `max-height`). El layout pasó de 3 a **2 columnas** (config | destacada+puntuación+más-contraseñas apiladas) — ver bullet de layout más arriba — así que las dimensiones se recalcularon para ese esquema. Valores actuales (fueron ajustándose en varias rondas, cada una pedida explícitamente):
    - Config: `w-100 h-155` → 400×620px.
    - Destacada: `w-210 h-44` → 840×176px.
    - Puntuación y "Más contraseñas": `w-210 h-54` cada una → 840×216px (mismo ancho que destacada porque las 3 están apiladas en la misma columna; mismo alto entre sí porque el usuario pidió explícitamente que esas dos sean iguales entre ellas, pero la destacada más chica). El ancho de estas 3 subió varias veces en rondas sucesivas (652→692→732→800→840px) — si se pide de nuevo "más ancho a las 3 cards", es sobre estas mismas.
    - Gap entre cards (grid principal Y entre las 3 cards de la columna derecha): `gap-1.5` → 6px exacto.
    - **Regla de altura, ajustada para cerrar exacto (no aproximado)**: alto de config = alto destacada + gap + alto puntuación + gap + alto "Más contraseñas" → 176+6+216+6+216 = **620 = config**, exacto. (Antes había una diferencia de 4px por redondeo — el usuario pidió explícitamente ajustar hasta que cierre sin diferencia, se logró bajando la destacada de `h-45` a `h-44`, no tocando puntuación/mas).
    - Padding interno: **las 4 cards en `p-4` (16px)** — el `CARD` constante compartido se bajó de `p-6` a `p-4` para todas (pedido explícito, antes la destacada tenía un override puntual a `p-4` con `!important` mientras el resto seguía en `p-6`; ahora es parejo así que no hace falta el override).
    - Confirmado con `getBoundingClientRect()` que las 4 cards miden **exactamente lo mismo en Random y en Memorable**.
  - **Toggle Random/Memorable centrado horizontalmente** dentro de la card de config — envuelto en `<div className="flex justify-center">` (el pill en sí sigue `inline-flex`, no se le puede poner `mx-auto` directo por no ser block-level).
  - **Caption de tiempo de crackeo**: pasó por `text-sm`→`text-base`→(bajó de nuevo con la reducción general de tipografía, ver más abajo) y `min-h-10 line-clamp-2`→`min-h-18 line-clamp-3`→**`min-h-6 line-clamp-2`** (valor final). El `min-h-18` (72px, reservado para 3 líneas) se sintió como "mucha distancia" hacia el link de abajo — el motivo real no era el margen (`mt-1`, ya achicado a 4px) sino que el texto casi siempre entra en **1 línea** (la card ahora es bastante más ancha que en el diseño original de 3 columnas), así que ese `min-h` grande dejaba ~48px de aire vacío DENTRO del párrafo antes de llegar al margen. `min-h-6` (24px = 1 línea exacta a `text-sm`) resuelve el caso común sin aire de sobra; `line-clamp-2` sigue de safety por si el texto alguna vez necesita 2 líneas. **Lección**: si un gap "se ve grande" pese a un margen chico, revisar primero si hay un `min-h`/`line-clamp` en el elemento de arriba reservando espacio vacío — no asumir que el margen es el culpable.
  - **Tipografía de toda la página bajada un paso** (pedido explícito, "reduce un poco el tamaño de las letras incluyendo el título"): `h1` `text-3xl sm:text-4xl` → `text-2xl sm:text-3xl`; subtítulo `text-lg` → `text-base`; contraseña destacada `text-xl` → `text-lg`; título del modal de vulnerabilidad `text-xl` → `text-lg`; el resto del contenido (labels, opciones, botones, badges, items de "Más contraseñas", etc. — todo lo que estaba en `text-base`) bajó a `text-sm` en bloque. El link "¿Cómo saber si...?" se dejó en `text-sm` sin bajar más (ya era el texto más chico interactivo de la página, bajarlo a `text-xs` lo hacía sentir demasiado chico para un link).
  - **Link "¿Cómo saber si mi contraseña es vulnerable?"** debajo del caption de crackeo, dentro de la card de Puntuación (pedido explícito, mismo lugar que Proton Pass tiene su link equivalente). Abre un modal propio (`infoOpen` state) que **sí respeta dark mode de verdad** (`dark:bg-slate-900 dark:text-slate-100` etc., a diferencia de `PreviewModal` que es siempre claro a propósito — ese modal es visor de imagen, este es de texto, no aplica la misma regla). Es texto, no imagen, así que **no** reusa `PreviewModal` tal cual, queda inline en `Contrasenas.tsx`; si se repite este patrón de "modal de texto" en otra tool, ahí sí extraerlo a un componente compartido.
    - Panel `max-w-2xl` con **borde `border-2` en emerald** (`border-[#10b981] dark:border-[#34d399]`, hex fijo en vez del nombre de Tailwind `emerald-500` — no cambia nada visualmente, pero descarta cualquier duda sobre el espacio de color `oklch` que usa Tailwind internamente). Backdrop en `bg-slate-900/95` (no `/80` como el resto de overlays del sitio) — **con `/80` el borde se veía "degradado"**, pero no era un gradiente real (confirmado con `getComputedStyle`, mismo color sólido en los 4 lados): era una ilusión óptica de contraste, el fondo semi-transparente dejaba ver distinto contenido de la página detrás de cada tramo del borde. Subir la opacidad del backdrop lo resolvió sin tocar el color en sí. Si aparece este mismo "gradiente falso" en otro borde sobre un overlay translúcido, revisar esto primero antes de tocar el color.
    - Contenido: resumen propio (no copiado) basado en NIST SP 800-63B — el usuario pasó como referencia un artículo largo de Proton/Richie Koch y pidió explícitamente **buscar una fuente distinta** y, en una segunda vuelta, un tono **más cálido y convincente** ("como si se hablase con un niño" — analogía de la contraseña como llave de casa, mantenida en varios de los bullets, más una línea de cierre motivadora en emerald). 5 bullets + cierre + atribución a NIST. **Ojo con el voseo**: la primera versión tenía "Evitá"/"Fijate" colados sin querer — el proyecto usa español neutro PE sin voseo (ver `## Copy / idioma`), corregido a "Evita"/"Revisa".
  - **"Excluir ambiguos" eliminado** (pedido explícito) — se sacó el state `excludeAmbiguous`, la regex `AMBIGUOUS`, y el parámetro correspondiente de `buildCharset` (ahora solo recibe `active`). Si se vuelve a pedir, no quedó nada a medio borrar por lo que se puede reintroducir limpio.
  - **Opciones de charset/passphrase** como filas clickeables tipo checkbox (casillero + nombre + muestra a la derecha, ej. "Mayúsculas ABC") — no son toggle-cards como el selector de motor de Ocr, patrón nuevo específico de esta tool (constante `OPTION_ROW` con las clases base compartidas). `CHAR_OPTIONS` centraliza nombre/muestra/charset por tipo (símbolos usa `SYMBOLS = '!@#$%^&*()-_=+[]{}|;:,.<>?'`, reusado también como set de símbolos para el separador "Números y símbolos" del modo Memorable).
  - Si se desmarcan los 4 tipos en modo Random (charset vacío), no rompe: la card central muestra "Elegí al menos un tipo de carácter." en vez de una contraseña. En modo Memorable esto no puede pasar (siempre hay wordlist).
  - **Gauge de puntuación**: semicírculo SVG con `pathLength={100}` + `strokeDasharray`/`strokeDashoffset` en base 100 (evita trigonometría manual para el arco) — progreso continuo (`Math.min(bits / 100, 1)`, no en 3 saltos). Color del trazo y el badge de texto ("Débil"/"Media"/"Fuerte") reusan la **misma excepción de paleta roja/ámbar/esmeralda ya documentada** para el badge de confianza de Ocr (semáforo de estado, no nuevo acento de marca) — umbrales en bits de entropía: <40 débil, 40-60 media, ≥60 fuerte. Bits se calculan distinto según el modo (`getEntropyBits` para Random, `getPassphraseBits` para Memorable — este último suma la entropía del separador random cuando aplica).
  - **Estimación de tiempo de crackeo** (`estimateCrackTime`, asume 10^10 intentos/seg — ataque offline rápido, estimación conservadora): convierte bits de entropía a segundos y elige la unidad más grande que quepa (segundos → siglos), con singular/plural correcto (`1 hora`, no `1 horas`) y buckets "Miles de .../ Millones de ..." para números muy grandes en vez de mostrar el número exacto.
